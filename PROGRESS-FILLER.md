# Progress filler — targeted gap sweep for one country (procedure)

*(Cowork, 2026-08-26, from Bill's outline in `prep/country-progress-filler.md`; revised same day after CC's verification — gap source corrected to the frame/held set difference, REJECTED verdict added, drop-list write path, §7a authorisation and re-run policy stated. Trigger: "**run the progress filler for {ISO}**". First run is **ZAF**, and the first run is the evidence — this is a **throughput investigation** before it is a gap-filler, so the accounting in §7 is a deliverable, not overhead. §7 was rewritten on 2026-08-26, after ZAF completed end to end, because it had been written in dollars and the constraint is Bill's week.)*

## 0. Authorisation and boundary — read before running

**This is the one Corpus-side process authorised to fetch** *(Bill, 2026-08-26)*. The standing rule that Corpus does not probe (`documentation/report-layer.md` §4) is not changed by this file: it is suspended inside this procedure only, because Bill wants the sweep run here and the returns handed to OSINT. Nothing else in Corpus fetches.

**Nothing is written to `C:\OSINT`, ever.** Candidates are staged to **`C:\corpus-osint-xfer\new-queue\`** and nowhere else. That folder is **Bill's hand-carry into OSINT** — a file left there is **not queued for ingest until he moves it**, so the run finishes by saying plainly that the batch is staged and undelivered.

**Nothing this run finds enters a report directly.** No write to `indicators.csv`, the ledger, or any document. The loop is: stage → Bill hand-carries → OSINT ingests to `raw/` → mirror refreshes → a later BUILD maps the new sources and moves the indicator. A staged file that never comes back through ingest changes nothing, which is correct.

**Ingest adjudicates, this run does not** — same as every OSINT sweep: no value judgement at staging, scope and origin screening only (§4).

**Precondition**: the Exa MCP (`agent_run` and the fetch tools) must be available in the CC session running this — it normally lives OSINT-side. If it is not connected, stop and tell Bill; do not substitute another search route, because the route being measured is Exa's.

**This is a second gap-probe pass, and it is authorised as one.** OSINT's `reference.md` §7a rules that gap probes are *"the acquire pass's, and no other's"*, precisely on the cost argument this run exists to measure. Bill authorised this pass on 2026-08-26 as a deliberate, scoped exception: its objects are **frame indicators**, not the named documents §7a's acquire pass chases; its route is the share, not OSINT's queues; and its purpose is to measure what a probe of this kind consumes. An OSINT session reading this file should read authorisation, not breach.

**Re-run policy — a searched nil is not re-bought** *(the rule both `report-layer.md` §4 and `reference.md` §7a state: a re-search over an unchanged base returns the same nothing at full price)*. The test is a **subject row count, recorded at probe time**: each run CSV row carries the count of the unit's ledger rows for the gap's subject (`subject_rows_at_probe` — the subject is the only key a gap has, since by definition it holds no `indicators.csv` row). A prior `nil` is **skipped** while the current count equals the recorded one, and re-opened when it differs — an arrival moves the count whatever its `published` date, which matters because an old document ingested late is exactly what Brief 1 exists to find. A skipped gap is carried in the new run CSV with outcome `skipped-prior-nil`, so the accounting stays whole. **The key is coarse, and errs open**: under a subject with zero ledger rows the skip holds until the filler's own staging comes back through ingest, but under a populated subject *any* arrival re-opens *every* nil beside it — on ZAF's shape, 18 of the 44 gaps sit under empty subjects where the skip is reliable, and 15 under subjects holding 5–22 rows where it will re-buy some nils. Re-probing too often is the right direction to err; just don't read this as a per-indicator memory.

## 1. Input — the gap list

The gap list is a **set difference**: every `indicator_id` in `lookups/indicators.csv` (the frame, 121 rows) **absent or blank** in `outputs/reports/{ISO}/indicators.csv` (the held view) — blank because the renderer treats an empty `progress` as *No evidence* too, so a held row with nothing in that column is a gap the plain difference would miss. The renderer fills those absent rows in as *No evidence* at bake time, so the held CSV itself contains no gap rows — reading it for them returns nothing *(CC's verification, 2026-08-26, correcting this file's first draft)*. The difference is also the cleaner source: the frame carries the Topic L2 slug §5 needs and the Level-1 grouping §6 batches by, with no HTML parsing. ZAF currently: 121 − 77 held = **44 gaps**, and per the frame every one is a named question: country × Topic L2 × indicator.

## 2. The two briefs per gap indicator

Each gap gets **two Exa Agent briefs** (`agent_run`, `effort: "medium"`), composed per `SWEEP-COUNTRY-DEEP.md` §3 — a natural-language objective with `{country}` and the indicator filled in, the date range stated explicitly, per-item reporting of URL / title / publisher / date / one line on why it matters, and the standing instruction to prefer primary and official sources.

**The objective names the chapter, the topic and the indicator together, as `{topic_l1} — {topic}: {indicator}`** *(2026-08-26, the first run's finding)*. The indicator alone is not a searchable object for a large part of the frame: **35 of the 121 rows are one or two words**, and one family is unusable on its own — all seven `dpi.mis--*` rows are bare nouns (Health, Education, Justice, Tax, Customs, Land, Social protection) that mean nothing without their Topic, *Sectoral management information systems*, and the seven `dpi.registry--*` rows are the same shape. Composed the old way, Brief 1 for `dpi.mis--land` read *"Establish whether **Land** exists in South Africa at all"*, and the Agent correctly reported it unresolvable. **The Level-1 chapter is needed as well as the Topic, and one row proves it**: `finance.mou--strategic-relationships` has Topic *MoUs and other agreements*, which still does not say **finance** — so the first run searched "strategic relationships" unanchored and returned ten general-government MoUs (DHET–Microsoft, SA–Netherlands ICT, DSTI–Huawei) against three that were actually about finance. The chapter is the missing anchor, and the frame carries it. **Relegating either to a trailing context line is not enough — both belong in the objective sentence.**

- **Brief 1 — baseline, no date restriction.** Does this thing exist at all, and what is its standing state? For *{topic_l1} — {topic}: {indicator}* in *{country}*: the instrument, system, institution or published figure itself, its founding or enacting act, and any dated authoritative statement of its current position. **Ask for the single most authoritative document, and rank what else it returns** — §4a keeps one.
- **Brief 2 — progress, windowed.** Movement on *{topic_l1} — {topic}: {indicator}* in *{country}* since the **first day of the current month, one year back** (a run in August 2026 searches from 1 August 2025) — matching the progress report's window. **Ask for the two or three most significant movements, ranked, one item per distinct event** — §4a keeps two.

**Ask the brief for a ranked shortlist, not everything it can find.** The cap in §4a is applied on Corpus's side with the bodies in hand, so the ranking is a hint and never the decision — but a brief that asks for the most significant items returns fewer and better candidates, which is the one saving available *upstream* of the fetch. The first run asked for everything and pulled 1,006 candidates to keep 132.

**Exclusions are stated in the brief, then enforced at staging** — `agent_run` has no hard domain filter; the firewall is §4.

## 3. Fetch and capture — OSINT's machinery, unchanged

**The Agent returns leads, never bodies; nothing the Agent writes is ever staged.** Every candidate goes through fetch → verify → classify → stage exactly as `SWEEP-DAILY-OFFLIST.md` runs it, under the standing capture rule in `C:\OSINT\wiki\capture-rule.md`: full verbatim body, never a search excerpt or an AI synthesis, `body_completeness` marked honestly, truncated captures flagged not retried. **Never trust the Agent's dates** — establish `published` from the fetched page (`SWEEP-COUNTRY-DEEP.md` §3a records what that mistake cost).

## 4. Screening and dedup — best-effort against a mirror

- **Origin screen**: run the script, not the prose — `python C:\OSINT\scripts\origin-screen.py` in its `--domain a.com b.net` mode, **one command per batch before fetching** (that mode exists for exactly this case, and the script makes no writes; the prose file `wiki/origin-screen.md` is its spec; the path is absolute because a Corpus session's cwd is not the mirror, and both scripts derive their root from their own location, so an absolute call is correct from anywhere). It reads the mirror's `logs/drop-list.csv` (stale-read caveat below applies). **The screen's contract is that an adjudication is written, and Corpus cannot write OSINT's list** — so any new watch/drop adjudication this run makes goes to **`C:\corpus-osint-xfer\progress-filler-drop-list.csv`**, header **verbatim** `domain,network,status,rule,added,note,,` — including the two trailing empty fields, **and every row written at the same 8 fields** (the live file's ragged tail is not the model; "same columns" composed from memory is how a shared file forks) — and §8's note asks OSINT to append those rows to its own list. An adjudication noted but not written is the failure the screen exists to prevent; this is the writable path this route has.
- **Scope**: drop what is not our subject, coded from `reference.md` §7's closed table. Every drop logged (§7 below), nothing discarded silently.
- **Dedup before fetching**: grep the mirror's `logs/sweep-url_log.md`; run `python C:\OSINT\scripts\raw-url-index.py --check` read-only against the mirror's index — `DUP-EXACT`/`DUP-SLUG` skip, **`REJECTED` drops** (`--check` loads `lookups/rejected-urls.csv` itself, the store that outlives the record: dropped, never fetched, never read), `FLAG-SLUG` never skips; cross-check what already sits in `new-queue\`.
- **The mirror caveat**: `C:\OSINT` is a mirror, so its logs and index read as whatever the last sync left. A URL absent from them is *probably* new, not certainly — this dedup is a cost-saver, not a guarantee, and OSINT's ingest remains the authoritative door where any duplicate that slips through is settled with the body in hand.

## 4a. Selection — the cap, and why it is Corpus's to apply

**Hard cap: per indicator, one baseline and two progress items. Three, maximum.** *(Bill, 2026-08-26, on the first run's return: 536 documents for 44 gaps is more than the ingest they are handed to is worth.)* Everything above the cap is **not staged** — the fetch has happened, the body has been read, and the item is recorded in the unselected register below rather than passed on.

**The cap is a maximum, never a quota.** Where two survive, stage two; where one does, stage one; where none does, the indicator is `nil` and that is the finding. Padding to three to fill the cap is the failure this section would cause if it were read as a target.

### What wins

- **The one baseline** is the thing that establishes the indicator exists and what it now is: the instrument, system or published figure **itself**, not commentary on it and not the announcement of it. The operative version beats a superseded one; the primary document beats the news of it; a statute beats a summary of the statute. Where the baseline is a *number* rather than an instrument, take the most recent authoritative publication of the series.
- **The two progress items** are the two that move the indicator furthest inside the window. **Two distinct events, never two reports of one event** — that is the commonest way a cap gets wasted. A dated event with a stated position beats a restatement of a known one; a primary source beats its syndication; a completed step beats an announced intention.
- Where the baseline document *also* carries the in-window movement, it counts once, as the baseline, and the indicator stages two rather than three. Do not stage a document twice under two headings.

### Why this is not the value-drop that sweeps are forbidden

`reference.md` §7 is explicit: **a sweep may drop on scope, never on value** — because value is *"whether the item adds to what the wiki already holds"*, and that *"needs the body and the compiled base, so it is ingest's alone."* This section drops items an ingest would have admitted, so it has to answer that rule rather than skirt it.

**It answers it on the rule's own terms.** The two things §7 says the judgement requires are the body and the compiled base, and this run has both: the bodies are fetched before selection happens, and the compiled base is the progress report — the frame, the indicator's own row, and what the report already says about it. **OSINT has none of that.** The frame is Corpus's file, the report is Corpus's output, and the question each gap asks — *does this document answer this named indicator* — is one only the side holding the frame can put. That is nearer scope than value: not *do we already have it* but *is it the thing we asked for*.

**So the cap is applied where the evidence to apply it lives, and the fact is declared, not buried.** §8's note tells OSINT the batch is capped and by what rule, because a thin batch that does not say it is capped reads as a thin sweep. Anything the cap excludes is recorded, not destroyed — an unselected item is one decision away from being staged, and none of it needs re-searching.

### The unselected register

**`logs/progress-filler/{ISO}-YYYY-MM-DD-unselected.csv`** — every fetched candidate the cap excluded: `indicator_id, url, title, publisher, published, brief, why_not`. `brief` is `baseline` or `progress`; `why_not` is free text, one clause.

This file is the reason the cap is cheap. The Agent spend has already been paid by the time selection happens, so discarding the leads would mean buying them again — and §7's evidence is that the leads are the cheap half anyway, which makes keeping them cheaper still. A later decision to widen the cap, or a gap that turns out to need more, is served from this register **without a single new `agent_run` call**. It is Corpus-side and stays Corpus-side — it is a list of leads, not evidence, and nothing in it is a source until it is staged and ingested.

### Where it runs

**The sub-agent selects, before staging**, because it holds the bodies and its own indicator's context, and because staging then throwing away is wasted writing. The parent audits the result against the cap on merge (§6) and is the backstop: **an over-cap indicator is the parent's to trim**, not something to hand on and hope ingest sorts out.

## 5. Staging shape

Flat to `new-queue\YYYY-MM-DD-slug.md`, best-effort frontmatter per the daily sweep's schema (`SWEEP-DAILY-LIST.md`), with `place:` = the ISO-3, the indicator's `Topic L2` slug first in `topics:`, and `sweep_batch: progress-filler-{ISO}-YYYY-MM-DD` — the batch label is what tells OSINT's ingest where these came from.

## 6. Delegation

One country per run. **The parent applies §0's skip first** — one cheap read of the prior run CSVs — writes the `skipped-prior-nil` rows itself, and slices only the **live** gaps, so batches are sized on work rather than part-filled with no-ops. Then **~10–12 live gaps per sub-agent, grouped by Level-1** so related briefs are screened and deduped side by side — **merging adjacent small chapters to fill a batch**, which the label example below already shows, because the chapters are not the right size on their own: ZAF's 44 gaps sit across ten Level-1 chapters and only DPI (11) reaches the band, seven holding five or fewer and two holding one. Strict grouping would spawn ten mostly-empty sub-agents; merged, ZAF is four. The parent owns every spawn, no sub-agent spawns another, and each is labelled with its slice (`filler ZAF 2/4 dpi+digital`). Each sub-agent returns a terse tally only — per indicator, the §7 row fields (`outcome`, counts, `subject_rows_at_probe`) — never bodies. **On merge the parent audits §4a's cap** — no indicator above one baseline and two progress — and trims any that is over, because a cap nobody counts is a suggestion. **Cross-queue dedup is the parent's too, and only the parent's**: five sub-agents writing to `new-queue\` concurrently cannot check each other, and the first run left 48 redundant files across 44 URLs that way. One pass after the batches return, keeping `full` bodies over `excerpt`. Where two captures of one page disagree on `published`, **record the conflict in the survivor's `note` rather than picking** — it happened ten times on the first run, and ingest settles it with the document in hand.

## 7. What a run consumes — the actual deliverable

**The budget this run spends is Bill's week, not money** *(Bill, 2026-08-26)*. He works on a fixed weekly allowance and nothing else: when it is gone he is dormant until it resets, and buying more is not a lever he uses. So the question a filler run has to answer is **how much of a week it takes and what that displaces**, and an answer denominated in dollars is an answer to a question nobody is asking. This section was written the other way round — it asked for spend per pass and yield per dollar — and the first end-to-end run showed why that mattered: the priced half was the cheap half.

Two files, both Corpus-side (`logs/progress-filler/` does not exist yet — the first run creates it):

- **`logs/progress-filler/{ISO}-YYYY-MM-DD.csv`** — one row per gap indicator: `indicator_id, subject, briefs_run, candidates_returned, fetched, staged_baseline, staged_progress, not_selected, dropped, drop_codes, outcome, subject_rows_at_probe`. `staged_baseline` is 0 or 1 and `staged_progress` is 0, 1 or 2 — **the cap is auditable from this file alone**, which is the point of splitting the old `staged` count in two. `not_selected` counts what §4a excluded, and those items are listed in the unselected register beside it; it is **not** a drop and must never be coded as one — `drop_codes` stays `reference.md` §7's closed vocabulary, describing candidates that failed screening. `outcome` is its own closed set of three — `staged` / `nil` / `skipped-prior-nil` — because `drop_codes` is `reference.md` §7's closed vocabulary and codes **candidates**, not indicators, and must not be bent to carry an indicator state. A `nil` (both briefs ran, nothing survivable came back) is **a searched absence, which is itself the finding** the coverage question needs; `subject_rows_at_probe` is what §0's re-run policy reads.
- **`documentation/progress-filler-cost-{ISO}.md`** — the summary the scale-out decision reads. *(It was `prep/` until the first run put it there and found `prep/` is gitignored — an untracked deliverable is no deliverable, and `CLAUDE.md` puts the analysis behind a decision in `documentation/` anyway. The filename keeps the word **cost** because the ZAF file is already cited under it and a name is not worth breaking a citation over; what it records is throughput.)* Record the run in **four stages, each with its own session count and wall time**, because they are separated by an OSINT ingest and a mirror refresh and cannot be done in one sitting: the **sweep** (`agent_run` count and effort, candidates returned, fetched, staged after §4a's cap), the **stage 4 read** (sources reaching the ledger, rows minted, rows moved), the **mapping** (indicators moved off *No evidence*, rows rewritten), and the **render**. Then state **yield** as gaps closed against gaps probed, and against sessions spent.

**The measurement the pilot exists to produce is a per-country session count, and ZAF gave it** *(2026-08-26)*. The sweep was the visible half and the cheap one: 44 gaps × 2 briefs, 1,006 candidates, 536 staged, capped to 126, one afternoon. The expensive half was everything after the ingest came back — **119 unconsidered sources read into 64 minted ledger rows and 14 moves, taking the ledger from 153 rows to 217, then 43 indicator rows drafted and 4 rewritten, then the render** — and that was a working session on its own. A scale-out estimate that counts only the sweep is therefore wrong by roughly the whole of the work, which is what the dollar framing hid.

**The week is shared with OSINT, and OSINT is the heavier consumer** *(Bill, 2026-08-26)*. Both sides run on Opus against the one allowance. What it has to cover first is OSINT's **sweeps every night to the end of the week**; Corpus's cycles and bulletins draw on the same pool and are not the pressure at present. The lever Bill pulls when the arithmetic stops working is a **mid-week downgrade to Sonnet** on whichever side is consuming most — he watches OSINT for this — and it is a downgrade rather than a pause or a purchase, so the work continues at lower quality rather than stopping.

Three things follow for a filler run. It is **never weighed against nothing**: the question is whether the week can carry it *and* the nightly sweeps, and a country's filler that would put the sweeps at risk is not a run to start. Its four stages are **already separated by an ingest and a mirror refresh**, so they are the natural places to stop if the week is tightening — stopping between them costs nothing, and stage 4 is resumable in any case because it reads a slug set difference. And the run's closing report to Bill is what the next scheduling decision is made on, so §8's fourth step is a measurement rather than a courtesy.

**So the lever to reach for is not the one this section used to name.** Merging the briefs or dropping effort trims the half that costs least. What actually bounds a national pass is the downstream reading, and the levers on it are a tighter cap at §4a, fewer gaps probed per country, or accepting a thinner ledger update — each of which trades coverage for a week, and each of which is Bill's call rather than the run's. State the trade in the summary; do not take it.

A searched nil is recorded **in the run CSV only** — it is what §0's re-run policy reads. It is not stamped anywhere else: `probe_at` is a `gaps.csv` column belonging to the ledger's ***Not held*** vocabulary, a different layer with a different closed set, and the indicator file has no probe field by design.
